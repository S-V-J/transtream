Built for Developers Who Own Their Audio

Every design decision optimizes for local-first control, auditability, and zero external dependencies.

Live WebSocket Ingestion

100 ms binary chunks stream directly from the browser over WebSocket. Incremental on-disk buffering with graceful partial save on disconnect. Rolling preview at beam=1 while you speak.

Single Input Contract

Every audio source — mic, upload, API — becomes 16 kHz mono 16-bit PCM WAV via FFmpeg before any intelligence runs. VAD and Whisper see exactly one format. No drift.

Durable Job Queue

Leases (120s), heartbeats (30s), startup recovery sweep, bounded retries (3), cooperative cancellation. Workers survive restarts; orphans reclaimed automatically.

Two Segment Timelines

Acoustic (Silero VAD) and linguistic (Whisper) segments both stored, told apart by source column. Neither is authoritative — both feed word-level alignment later.

Per-User API Keys

Keys shown once, stored hashed (PBKDF2), fingerprinted for O(1) lookup. Scoped permissions, instant revocation, 120 req/min rate limit per key with Retry-After headers.

Translation + TTS

NVIDIA Nemotron-3 Ultra (primary, 14 parallel / 30 RPM) with Argos Translate fallback. Piper TTS with 8 voices (en, fr, hi, es, de, zh, ja, ar). WebSocket-streamed PCM.

Three Ways In, One Pipeline

The moment two code paths do the same job, they start to drift quietly because both appear to work. TranStream enforces one entry point per job.

1

Live Microphone

  • • MediaRecorder, 100 ms binary slices
  • • WebSocket frames → AudioConsumer
  • • Pipeline runs inline after Stop
  • • Rolling preview on isolated thread
2

Browser Upload

  • • Multipart POST to /studio/upload/
  • • 64 KB streaming chunks, magic-byte validation
  • • Size cap enforced twice (declared + actual)
  • • Take + Job(QUEUED) → worker picks up
3

Public API

  • • Bearer key from /account/keys/
  • • POST /api/v1/transcriptions
  • • Same upload_service, same queue
  • • Poll GET /api/v1/jobs/{id}

Unified Pipeline: process_take()

  1. 1. normalize — FFmpeg → 16 kHz mono 16-bit PCM WAV
  2. 2. segment — Silero VAD (ONNX) → acoustic timeline
  3. 3. transcribe — Faster-Whisper (float32 array, never path) → segments + LID
  4. 4. translate — Nemotron-3 Ultra / Argos → Translation rows
  5. 5. synthesize — Piper TTS → WebSocket-streamed PCM audio

Why Local-First?

After years of moving voice across SIP trunks and RTP streams, I like knowing exactly where the audio is at every moment. In TranStream it's on your disk, in your SQLite file, and in a model running on your CPU. There's no cloud API, no telemetry, and no key to manage — unless you choose the NVIDIA Nemotron translation endpoint.

Inspiration: Telephony Engineering

4+ years on GTD 5 / DMS 100 switches, SIP/ISUP debugging from pcap, Asterisk/Kamailio builds. Audio is a stream with a strict contract at its boundary.

Inspiration: Voice AI Integration

Bridged live Asterisk calls into voice AI engines via AudioSocket/WebSocket. Same shape as TranStream's mic path — live audio crossing a socket into a model.

Inspiration: Grounded Voice Search

Built document indexing queried by text or live voice using Whisper + conversational AI. TranStream is what that became once audio stopped leaving the machine.
